# Вложения — обычные файлы: план

> Исполнение: superpowers:executing-plans, сам, задача за задачей. Описание — `docs/specs/2026-11-16-attachments-as-files-design.md`.

**Цель:** голый файл без `.md`, картинки на месте вставки в тексте, файлы в папке вложений по настройке Obsidian, старое читается как было.

## Общие правила

- Существующие файлы человека не переносить и не переписывать без его действия. Проверка — копия College, md5 до и после (задача 7). Без неё сборку людям не отдавать.
- Тесты — только затронутые файлы, с потолком (`systemd-run … -p CPUQuota=500% -p MemoryMax=5G`).
- Код — Read + Edit, тексты коммитов и комментарии по-русски.

## Что проверить отдельно

1. Гонка: голый файл перенесён из входящих, а строки карты файлов ещё нет — сверка не плодит дубль (задача 2).
2. Повышение: метка у голого файла — рядом `.md`, файл на месте, после пересборки метка жива (задача 4).
3. Одно имя в двух папках — вставка получает «закат 2.jpg» или путь, а не чужую картинку (задачи 2, 4).
4. Корзина заметки не уносит вложение, на которое ссылается другая заметка (задача 4).
5. Старая заметка с хвостом и каталогом `Заметка/` читается и пишется без переноса файлов (задачи 2, 4, 7).

### Задача 1: место вложений по настройке Obsidian

**Файлы:** `lib/services/vault/vault_layout.dart`, тест `test/services/vault/vault_layout_test.dart`.

**Даёт:**
- `({bool obsidian, String? setting}) readAttachmentSetting(Directory root)` — `.obsidian/app.json`, ключ `attachmentFolderPath`.
- `String attachmentFolderFor(String notePath, {required bool obsidian, String? setting})` — каталог от корня: `/` и пусто при `obsidian` → `''` (корень); `./` → каталог заметки; `./имя` → каталог заметки + `имя`; `имя` → `имя`; без Obsidian → каталог заметки.

Тест `место вложений: корень, рядом, подкаталог, общая папка, без Obsidian` — все пять случаев на `Stowa/Покупки.md`.

### Задача 2: чтение — оба вида

**Файлы:** `lib/domain/vault_note.dart` (хвост), `lib/services/vault/vault_reader.dart` (`_attachments`), тест `test/services/vault/vault_attachments_test.dart`.

- Хвост: строка `![[путь]]` в конце — старый хвост, только если `dirname(путь)` кончается на имя самой заметки (`Заметка/…`). Остальные вставки с путём остаются в тексте.
- `_attachments`: короткое имя ищется ещё и в папке вложений по настройке, затем по всему хранилищу по имени (указатель имён строится один раз за сверку, без служебного и корзины).
- Тесты: `старый хвост в свой каталог — вложения, текст чистый`; `вставка с путём в конце нового текста — остаётся в тексте`; `короткое имя находится в общей папке «Изображения»`; `файл в «Изображения», на который ссылается заметка, — не заметка-файл`.

### Задача 3: схема — заголовок дан приложением

**Файлы:** `lib/data/db/tables.dart`, `database.dart` (v20, миграция `addColumn`), `items_repository.dart` (`setTitleBody` и переименование ставят `title_auto = false`), `capture_service.dart` (подпись «Фото от …» — `true`; `retitleUntitled`/`retitleFileNames` трогают только `true`), `vault_reader.dart` (заметка-файл из файла — `true`), тест миграции и тесты сохранения.

`dart run build_runner build --delete-conflicting-outputs` после правки таблицы. `title_auto` в файл заметки не пишется (`_vaultItemColumns` не трогать).

### Задача 4: запись

**Файлы:** `lib/services/vault/vault_writer.dart`, тест `test/services/vault/vault_attachments_test.dart`.

- `_gather(id, folder, body)`: переносит только файлы из входящих (`.stowa/incoming/` и открытого скрытого), в папку вложений по настройке; имя свободно по всему хранилищу (база: пути вложений и карты файлов; диск: целевой каталог), иначе «имя 2»; переименованное переписывается во вставках текста. Файлы, уже лежащие в хранилище, не двигаются.
- Новая вещь: текст без вставок пуст, вложение одно, своего нет (`_bare(item)`: нет меток, напоминаний по времени и месту, закрепления, своих свойств, ручных связей, `created` не правлен) и не скрытая → голый файл в папке вещи, строка карты файлов на сам файл, `.md` нет.
- Голый файл и у вещи появилось своё или текст → `.md` рядом: текст + `![[файл]]`, текст в базе тоже со вставкой; файл не двигается; карта файлов → `.md`.
- `_writeLoose`: файл переименовывается только при `title_auto == false`.
- Хвост пишется только для вложений, которых нет во вставках текста (старые заметки).
- Корзина и возврат: вложения, на которые никто больше не ссылается, уходят в корзину вместе с заметкой и возвращаются; общие — на месте. Старые каталоги `Заметка/` — как раньше.
- Тесты: `новая заметка с фото: файл в «Изображения», вставка в конце текста, хвоста и каталога нет`; `одно фото без текста — голый файл, имя камеры`; `метка у голого файла — рядом .md, файл на месте, пересборка помнит метку`; `подпись «Фото от …» файл не переименовывает, своё название — переименовывает`; `одно имя в двух папках — «закат 2.jpg» и вставка с ним`; `корзина: своё вложение уходит и возвращается, общее остаётся`; `старая заметка с каталогом — запись ничего не переносит`.

### Задача 5: сохранение строкой

**Файлы:** `lib/services/capture_service.dart`, `lib/features/composer/line_dock.dart` (если вставки собираются там), тесты `test/services/capture_service_test.dart`.

- Текст + файлы → в конец текста `\n\n![[имя]]` по строке на файл (имя без номера входящих), заголовок — из текста.
- Один файл без текста → тело пустое (станет голым файлом). Несколько без текста вне папки → тело из одних вставок, заголовок — подпись «Фото от …».
- «Дописать» с файлами (`attach`) → вставки в конец тела.
- Тесты на три случая и на «Дописать».

### Задача 6: страница заметки

**Файлы:** `lib/features/item/item_screen.dart`, тест `test/features/item/…`.

- Вложения без вставки в тексте: у заметки с текстом — после текста, у заметки без текста — крупно, как сейчас.
- Тест: заметка «Текст» + фото без вставки — фото ниже текста.

### Задача 7: доказательство и эмулятор

- `tool/vault_safety_check.dart` (или тест под переменной `VAULT_COPY`): копия College во временную папку, md5 всех файлов, `rebuild` + `reconcile` + `drain`, md5 снова — печатает числа: всего, перенесено, изменено, добавлено. Ожидание: перенесено 0, изменено 0 (кроме служебного `.stowa/`).
- Эмулятор: сборка на GitHub, обновление поверх нынешней (старые заметки с каталогами), четыре фото в папку (голые файлы), заметка с текстом и фото (вставка в конце, картинка ниже текста), метка у голого фото (появился `.md`), удаление.
- `CLAUDE.md` проекта, коммит, пуш, проверка GitHub зелёная.
