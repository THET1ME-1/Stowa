# Stowa в браузере — план

> Исполнять по задачам, по порядку; каждая задача кончается зелёным `flutter test` (и `-t heavy`, где тронуто хранилище или синхронизация) и коммитом в main.

**Цель:** Stowa работает на https://stowa.work с хранением «в этом браузере», телефон не замечает перемен; потом рабочее пространство, папка и Stowa Sync.

**Описание:** `docs/specs/2026-11-17-web-design.md`.

**Стек:** Flutter 3.47 web (dart2js), drift 2.35 на `sqlite3.wasm` + `drift_worker.js` из выпуска drift 2.35.3, пакет `file` 7, `package:web` для OPFS и Web Locks, Caddy на сервере.

## Общие правила

- Код в `lib/` правится только Read + Edit; `dart format` — только по своим файлам.
- Телефон: `LocalFileSystem` обязан вести себя как `dart:io`. После каждой задачи с файлами — весь `flutter test` и `flutter test -t heavy`.
- Строки интерфейса — в 7 arb; подсказка — одно предложение.
- В документы не пишем адреса серверов и ключи: репозиторий публичный.

## Что легко сломать и чем ловим

1. Две вкладки пишут одну базу → тест замка в браузере (Playwright, две страницы).
2. Закрыли вкладку сразу после правки → тест: правка, `pagehide`, новая страница видит файл.
3. Копия из браузера на телефоне → тест `BackupService.restore` на архиве без снимка базы.
4. Переименование папки в браузере → тест `WebFileSystem`: `rename` директории переносит всё дерево и журнал.
5. Синхронное чтение крупного вложения в браузере → `WebFileSystem` бросает понятную ошибку, тест; места вызова переведены на асинхронное.

## Часть 1. Браузер с хранением «в этом браузере»

### Задача 1. База открывается и в браузере

- Файлы: `lib/data/db/raw_open.dart`, `raw_open_web.dart` (условный импорт `dart.library.js_interop`), `database.dart` (`DriftWebOptions` с `onResult` → `webDatabaseMode`), `backup_service.dart`; `web/` (`flutter create --platforms=web`), `web/sqlite3.wasm`, `web/drift_worker.js` из выпуска drift 2.35.3, их sha256 — в `web/README.md`.
- Проверка: `flutter test` зелёный; `flutter build web` проходит.

### Задачи 2–4. Файлы и запуск в браузере — сделано 17.11

Вместо замены 202 мест — подмена `dart:io` через `IOOverrides.global` только в браузере (`lib/core/fs/`: `web_fs.dart`, `web_store.dart`, `browser_storage*.dart`, `web_files.dart`), `Platform.*` — через `lib/core/platform.dart`, запуск — ветка `isWeb` в `main.dart`, хранилище — `/vault` как «одно место» (`vaultHome`). Тесты: `test/core/fs/`. Проверено в Chromium и Firefox: заметка пишется файлом в OPFS и переживает перезагрузку. Писатель хранилища возвращается к задачам под истёкшей арендой.

### Порядок дальше (хозяин: «делай по макету уже»)

Рабочее пространство (часть 2) идёт сразу после запуска, до задач 5–8.

### Задача 5. Чего нет в браузере

- Спрятать: «Поделиться», виджеты, «Под рукой», стикеры, отпечаток и замок, места и Wi-Fi, галерею, перенос Telegram и Keep, бота Telegram, превью ссылок и читалку, фон.
- `Image.file` и `FileImage` (20 файлов) → `vaultImage(file)`: на телефоне `FileImage`, в браузере байты из `fs`.
- Проверка: тест виджетов, что пункты скрыты при `isWeb`; ручной проход в браузере без красных экранов.

### Задача 6. Надёжность вкладки

- Web Locks: вторая вкладка — экран «Stowa уже открыта в другой вкладке» и «Открыть здесь».
- `navigator.storage.persist()`, предупреждение при первом запуске и «Сохраните копию» раз в 7 дней и после 50 правок.
- Предупреждение, если drift выбрал `sharedIndexedDb` или `inMemory`.
- Проверка: Playwright, две вкладки; правка и сразу закрытие — файл на месте.

### Задача 7. Копия туда и обратно

- В браузере: копия без снимка базы, собирается потоком и скачивается файлом; восстановление из выбранного zip с пересборкой указателя.
- Телефон: `restore()` принимает архив без снимка базы.
- Тесты: архив без базы восстанавливается на VM; копия из браузера (Playwright) открывается телефонным `restore()`.

### Задача 8. Выкладка

- `tool/web/build.sh`: `flutter build web --release --no-web-resources-cdn`.
- `tool/web/deploy.sh`: файлы на сервер, блок Caddy с COOP/COEP, `application/wasm`, кэш; запись DNS `stowa.work`.
- CI: задание `web` в `check.yml` собирает сборку.
- Проверка: https://stowa.work открывается, `crossOriginIsolated` истина, режим `opfsLocks`.

## Часть 2. Рабочее пространство

Компоновка по ширине ≥ 1000: доки слева и справа с панелями, вкладки и деление центра, плитка, настройки вкладкой, сочетания клавиш с настройкой. Подробный план — отдельным документом, когда закончится часть 1.

## Часть 3. Папка на компьютере (Chrome, Edge)

`showDirectoryPicker`, хранение разрешения, метка хранилища в `.stowa/`, переименование папки копированием.

## Часть 4. Stowa Sync в браузере

CORS на сервере синхронизации, ключ хранилища в браузере, порядок приёма «сначала заметки», устройство «Этот браузер».
