**Цель:** заметки Stowa живут обычными файлами `.md` с вложениями в папке, которую выбрал человек, и переживают переустановку; поиск, «Связано» и разбор работают с той же скоростью.

**Устройство:** база SQLite остаётся рабочим местом приложения и указателем для поиска, а папка хранилища становится правдой. Каждую правку, кто бы её ни сделал, ловят триггеры SQLite и ставят в очередь `vault_queue`; писатель переносит её в файлы. Обратно — читатель: при открытии сверяет файлы с базой и забирает то, что изменили снаружи (Obsidian, Syncthing, файловый менеджер). После переустановки читатель собирает базу из папки целиком.

**Стек:** Flutter 3.47.6, Drift (схема v6 → v7), Riverpod 3, пакеты `yaml` (чтение свойств) и `file_picker` (уже есть), свой канал `stowa/vault` в `MainActivity.kt`.

**Описание:** `docs/specs/2026-11-05-vault-files-design.md`.

## Общие ограничения

- Папку хранилища выбирает человек. `Documents` в окне выбора — только подсказка.
- Три пути на первом запуске: «Создать хранилище в памяти устройства» (по умолчанию), «Открыть папку как хранилище», «Хранить внутри приложения» (с предупреждением, что при удалении приложения заметки пропадут).
- Разрешение памяти устройства — `MANAGE_EXTERNAL_STORAGE` («Доступ ко всем файлам»), как у Obsidian.
- Строка очищается быстрее 100 мс, как сейчас: запись файлов идёт после транзакции, не внутри неё. Тест скорости `capture_service_test.dart` («укладывается в 100 мс») остаётся без изменений.
- Поиск, FTS, `word_forms`, `word_variants`, `search_query`, `search_rank`, `related.dart`, `folder_guess.dart` не меняются.
- Без Google и без своего сервера. Облачной синхронизации нет.
- Чужие файлы Obsidian Stowa меняет минимально: дописывает только `id` в свойства.
- Код по образцу соседнего: комментарий строкой над блоком, имена полными словами, правка только через Read и Edit.
- Строки интерфейса — на 7 языков через `tool/add_strings.py`.

### Уточнения к описанию, принятые здесь

- **Один корень файлов.** `filesRootProvider` становится корнем хранилища. Все относительные пути, которые уже лежат в базе (вложения, обложки, копии страниц, значки тегов), продолжают работать от него. Переносятся только папки: `covers/` → `.stowa/covers/`, `pages/` → `.stowa/pages/`, `tags/` → `.stowa/tag-icons/`, миниатюры → `.stowa/cache/thumbs/` (можно стереть, пересоздаются).
- **Новая установка сразу получает хранилище внутри приложения** (`<appSupport>/vault`), чтобы окно «Поделиться» и фон работали ещё до выбора. Выбор папки на первом запуске — это перенос этого хранилища.
- **Вложения в файле — строки `![[…]]` в конце**, после текста, по порядку. При чтении хвост из таких строк снимается и становится списком вложений, поэтому текст проходит круг без изменений, а Obsidian картинки показывает.
- **`.stowa/facts/<id>.json` хранит всё добытое о вещи:** факты с прогонами извлекателей (имя, версия, отпечаток), расшифровку голосового и описание от ИИ. Это добыто сетью или платным ключом, терять нельзя.
- **В свойствах файла `sorted_by`** (руками, правилом, ИИ): «ручное решение главнее ИИ» должно пережить переустановку. `sort_state` (очередь разбора) не пишется.

## Где внимательнее всего

Пять случаев, которых описание не называет, но которые больнее всего ударят по человеку. Тесты к ним вписаны в задачи-хозяева.

1. **Два заголовка дают одно имя файла** («Купить молоко» дважды, или «a/b» и «a:b» после чистки символов). Ждём «Купить молоко 2.md», ни один файл не затёрт. — Задача 1 и 4.
2. **Приложение убили посреди записи файла.** Ждём целый старый файл или целый новый, не обрывок: запись во временный файл и переименование. При следующем запуске очередь доделывает запись. — Задача 4.
3. **Заголовок или папка с символами, которые Android не пускает в имя** (`/ \ : * ? " < > |`, точка в конце, имя длиннее 120 знаков, эмодзи). Ждём рабочее имя, а настоящий заголовок — в свойстве `title`. — Задача 1.
4. **Файл правят одновременно Stowa и Syncthing.** Ждём, что ни одна правка не пропадёт молча: если файл на диске изменился после нашей последней записи, а в базе тоже правка — пишем свою версию рядом как «… (Stowa).md» и показываем обе. — Задача 6.
5. **Папку хранилища удалили или отозвали разрешение,** пока приложение закрыто. Ждём не пустую главную и не стирание базы, а экран «Хранилище не найдено» с «Выбрать заново» и «Открыть другую папку». — Задача 9.

**Файлы:**

**Потребляет:** `readVaultNote`, `VaultLayout`, `isServicePath`, `VaultFiles`, флаг `importing`.

**Даёт:**
- `class VaultReader { Future<VaultScan> reconcile(); Future<VaultScan> rebuild({void Function(int done, int total)? progress}); }`, `class VaultScan { int added, changed, removed, conflicts; }`.
- `reconcile()`: обходит хранилище (без служебных папок), сравнивает время и размер с `VaultFiles`. Изменился → читает и обновляет вещь, теги (создаёт недостающие), вложения из хвоста `![[…]]` и из папки вещи; `id` нет → новая вещь, `id` дописывается в файл (это единственная правка чужого файла). Файла нет → вещь в корзину базы (файл уже удалён, в `.trash/` не переносится). Папка верхнего уровня без записи в `folders.json` → новая папка Stowa. `[[Заметка]]` → ручная связь в `links`. Всё под флагом `importing`.
- **Конфликт** (случай 4): файл изменился снаружи после нашей последней записи, а вещь стоит в `vault_queue` — значит, правка есть с обеих сторон. Файл забирается как есть, а версия из базы пишется рядом как «<имя> (Stowa).md» новой вещью с пометкой. Syncthing-конфликт `*.sync-conflict-*.md` читается обычной вещью с той же пометкой.
- `rebuild()`: пустая база + хранилище → вещи, папки, теги, правила, выученное, холст из `.stowa/*.json`, факты и прогоны извлекателей из `.stowa/facts/` (конвейер не переделывает добытое), отчёт хода для полоски.
- Подпапки внутри папки Stowa читаются вещами её верхней папки (до вложенных папок шага 8).
