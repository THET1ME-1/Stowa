# Синхронизация Stowa — план

> **Для исполнителя:** superpowers:executing-plans, задачи по порядку, шаги с `- [ ]`.

**Цель:** хозяин входит в Stowa кодом с почты, и хранилище держится одинаковым на двух телефонах через сервер sync.stowa.work.

**Устройство:** движок на чистом Dart за портами (диск, сеть, состояние, аренда) в `lib/services/sync/`; сервер — отдельная служба на Dart в закрытом репозитории `THET1ME-1/stowa-sync` (`~/Projects/GitHub/stowa-sync`), Postgres `stowa-db` и бакет Hetzner `stowa-sync`; Caddy проксирует `sync.stowa.work` на 127.0.0.1:8792. Шифрует телефон, сервер видит только номера и зашифрованные куски.

**Стек:** Dart 3.13, Flutter, drift, `cryptography` (AES-GCM, HMAC-SHA256), `unorm_dart` (NFC); сервер — `shelf`, `shelf_router`, `postgres` 3, `minio` (S3 Hetzner), `mailer` (SMTP Brevo).

**Описание:** `docs/specs/2026-11-17-sync-design.md`.

## Общие правила

- Код править Read + Edit, без `sed` и скриптов.
- Тесты локально только затронутые файлы, с потолком из `CLAUDE.md`; весь набор — `check.yml`.
- Сервер: контейнер с `mem_limit 1g`, `cpus 2`, слушает только 127.0.0.1. Caddy — копия файла, `caddy validate`, `reload`, не `restart`.
- Письма Stowa: свой потолок 100 в сутки из общих 300 Brevo; повтор кода не раньше 60 секунд, не больше 5 кодов в час на адрес, 20 в час на IP; код живёт 10 минут, 5 попыток.
- В сборках Play и App Store про оплату ни слова. Подписку для проверки ставит хозяину команда сервера `admin grant <почта> <дни>`.
- Формат: в зашифрованном заголовке файла версия формата `v: 1` и размер части `chunk`. Часть — 8 МиБ.
- Путь файла → идентичность: `file = base64url(HMAC-SHA256(ключ хранилища, NFC(путь).toLowerCase()))`, первые 32 знака. Настоящий путь — в зашифрованном заголовке.

## Что синхронизируется

Всё хранилище, кроме: `.stowa/covers/`, `.stowa/frames/`, `.stowa/pages/`, `.stowa/articles/`, `.stowa/cache/`, `.stowa/incoming/`, `.obsidian/workspace*.json`, временных `*.tmp`. Открытая папка скрытого лежит вне хранилища. `.stowa/sealed/` и `.stowa/lock.json` идут как есть.

## Склейка

- `.md`: по трём версиям построчно (общая — тень последней синхронизированной версии). Правки в разных местах встают обе; одни и те же строки — остаётся свежее по времени правки, проигравший текст целиком уходит порту `loser(path, text)`, приложение кладёт его в историю заметки.
- `.stowa/*.json` и `.stowa/facts|history/*.json` (таблицы `{"таблица": [строки]}` или снимки): по трём версиям построчно по ключу `id` (иначе первая колонка); удалённое на одной стороне удаляется, изменённое на одной берётся оттуда, на обеих — свежее.
- Остальное: побеждает свежее по времени правки, прежнее остаётся ревизией на сервере.
- Общей версии нет (первое включение на втором хранилище) — `.md` и JSON склеиваются с пустой общей: строки обеих сторон объединяются без потерь.

## Защита

- Первый проход устройства (состояние пустое) ничего не удаляет на сервере — только объединяет.
- Обход папки упал или корень недоступен — проход прерывается без удалений.
- Пропало больше 30% известных файлов и больше 20 штук — удаления не отправляются, ошибка «Пропало много файлов — синхронизация приостановлена».
- Движок работает под арендой сверки `VaultReader` (тот же флаг в базе), пришедший файл кладёт временным файлом и переименованием; писатель такой файл считает правкой снаружи и не затирает (`_ExternalEdit`).

## Отложено

Свой пароль на ключ хранилища, прямая отправка в бакет, удаление аккаунта, живое соединение (вместо него долгий опрос `wait=25`), оплата, ночная копия базы (задача 8 — только скрипт и cron).

## Review Focus

1. Два непустых хранилища включены одновременно — ни один файл не пропал.
2. Обрыв посреди отправки большого файла — докачка с той же части, отпечаток совпал.
3. Одна заметка правится на двух телефонах в одну минуту — текст обоих в файле или в истории.
4. Кириллица в имени в NFD и NFC — один и тот же файл.
5. Аккаунт без подписки — сервер не принимает и не отдаёт файлы (402).

### Задача 4: Сервер

**Файлы:** репозиторий `~/Projects/GitHub/stowa-sync`: `bin/server.dart`, `bin/admin.dart`, `lib/api.dart`, `lib/db.dart`, `lib/mail.dart`, `lib/blobs.dart`, `migrations/001.sql`, `test/api_test.dart`, `Dockerfile`, `README.md`.

**API** (JSON, `Authorization: Bearer`):
- `POST /v1/auth/start {email, lang}` → 204; 429 `{retry_after}`; 503 письмо не ушло.
- `POST /v1/auth/verify {email, code, device}` → `{token, email, active}`; 401 неверный код.
- `GET /v1/account` → `{email, active, paid_until}`; `DELETE /v1/session`.
- `GET /v1/key` → `{key}` или `{key: null}`; `PUT /v1/key {key}` → 204, 409 если уже есть. Ключ лежит в базе зашифрованным главным ключом сервера `STOWA_MASTER_KEY`.
- `GET /v1/changes?since=N&wait=25` → `{cursor, more, changes: [{file, rev, deleted, meta, blobs, size}]}`, до 1000 за раз.
- `HEAD|PUT|GET /v1/blobs/{sha256}` — PUT проверяет отпечаток тела, до 17 МиБ.
- `POST /v1/files/{file} {base_rev, deleted, meta, blobs, size}` → `{rev, cursor}`; 409 `{rev}` если ревизия не та; 422 если нет части.
- Без подписки файлы, части и изменения отвечают 402.

**Таблицы:** `accounts`, `codes`, `mail_log`, `sessions` (хранится отпечаток токена), `files` (текущая), `revisions` (история 30 дней), `blobs`.

- [ ] Тесты против Postgres в docker на ноутбуке и бакета-папки: вход кодом, неверный код 5 раз — код сгорел, лимиты писем, 402 без подписки, конфликт ревизий 409, курсор и `wait`.
- [ ] Красный, реализация, зелёный, коммит, закрытый репозиторий на GitHub.
